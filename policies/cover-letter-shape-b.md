# Cover letter — Shape B: Blocks 1-4 (What / Why me / Why them / CTA)

Called by `playbooks/cover-letter.md` Step 4 when Step 2 picked Shape B. Read
`policies/cover-letter-writing-policy.md`'s shared rules first if you haven't already — don't
open `cover-letter-shape-a.md` too, this shape doesn't need it.

For a letter likely to be **processed by an ATS or a formal corporate pipeline** before (or
instead of) a person reading it closely: a standard vacancy posting, a large-company career
portal, a Greenhouse/Lever/Workday-hosted listing, a generic formal application. Genuinely
different genre from Shape A — different reader, different goal, different failure mode. Source:
adapted from `_sb/reference/cover-letter-framework-vacancy.md`'s Blocks 1-4 (that file stays the
full captured design doc; this is the operational version `cover-letter.md` actually calls).

## Plan

1. **What** — who the candidate is and what role they're applying for, one line.
2. **Why me** — 2-3 concrete reasons they're a fit, each backed by evidence (from
   `targeting-plan.md` if one exists, same sourcing as Shape A's Evidence step) — never "I am
   passionate and highly motivated," always a specific capability tied to what the posting asks
   for. In long-term mode this centers the recurring professional pattern; in task mode (rare for
   this shape, but possible for a formally-posted contract role) it centers the concrete
   deliverable match.
3. **Why them** — why this specific vacancy/company, using the vacancy's own vocabulary and any
   real, checkable detail about the company or role from the posting. This is the block that fails
   hardest generically — if there's nothing genuinely company-specific to say, say so and ask the
   candidate rather than manufacturing generic enthusiasm.
4. **CTA** — a short, plain close ("happy to discuss further," or similar) — no theatrics.

## Write

- Plain text, ~120-180 words total (a little more room than Shape A — Block 3 needs a real,
  specific sentence, not a generic one).
- A short greeting by name if the posting names a real contact/recruiter; otherwise open directly
  on Block 1 rather than inventing a name or using "Dear Hiring Manager." A short sign-off line
  (e.g. a name), not a full signature block.
- Formal but not stiff corporate voice — plain, direct sentences, no filler adjectives
  ("passionate," "results-driven," "dynamic").
- Use the vacancy's own terminology where it's genuinely true of the candidate — this shape is
  read by keyword-matching as much as by a person, so don't paraphrase away a real match.

## Self-check

On top of `cover-letter-writing-policy.md`'s shared checks:

5. **Retells the resume** — is this just the CV's bullet points restated in sentence form, with no
   actual argument connecting them to this role? If so, it needs an argument, not more bullets.
6. **Vocabulary match** — does it naturally use the vacancy's own terms for the capabilities it
   actually has, or does it paraphrase into generic synonyms that would score worse in a
   keyword-driven first pass?
7. **Why-them is real** — is Block 3 genuinely specific to this company/role, or would it read
   identically pasted into an application to a different company? A generic Block 3 is a
   Shape-B-specific failure this shape exists to avoid — fix it or flag the gap, don't ship it
   generic.
