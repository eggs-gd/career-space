# Cover letter writing policy

Shared by `playbooks/cover-letter.md`, which orchestrates (resolve the vacancy, decide mode and
shape, gather evidence, dispatch, save/show/render) but holds none of the writing technique
itself. Read `policies/generation-rules.md` first — the universal writing discipline this sits on
top of.

**This file is the shared rules only.** The actual plan/write/self-check technique for each shape
lives in its own file — read *only* the one `cover-letter.md`'s Step 2 picked, not both:

- `policies/cover-letter-shape-a.md` — Problem/Differentiator/Evidence/Scope/Core Message, for a
  letter likely read by a person.
- `policies/cover-letter-shape-b.md` — Blocks 1-4 (What/Why me/Why them/CTA), for a letter likely
  processed by an ATS or a formal corporate pipeline.

They're written for different readers and fail in different ways — don't merge them, and don't
read the other one "just in case." Shape is independent of **mode** (task-bid vs long-term role,
also decided in Step 2): mode still controls emphasis (what-you'll-get vs who-you-are) inside
whichever shape is chosen — a long-term role rendered in Shape B still centers who the candidate
is in Block 2, a task bid rendered in Shape A still leans on the concrete deliverable.

Both shapes keep three explicit passes — plan, write, self-check — in one conversation, genuinely
separate steps. The split exists because "write a persuasive letter" and "only say things you can
prove" pull against each other in one undifferentiated pass; keeping analysis structurally
separate from persuasion means the writing step has nothing to invent from — it only has the plan.

## Shared across both shapes

- Never mention anything the plan didn't include. Preserve ownership scope from the plan's
  evidence exactly (never upgrade "contributed to" into "led").
- Plain text only — no markdown formatting; this gets pasted into platforms/emails that don't
  render it.
- If the posting asked specific written-answer questions, answer them directly and factually —
  don't fabricate an answer `data/CV_GENERAL.md` doesn't support; say so and ask the candidate.
- Write from the plan alone, as if the raw Master CV weren't open — that's what makes the
  plan/write split actually work, not just a formality.
- Self-check is an independent pass — re-read the draft as if checking someone else's work,
  against the plan and the full Master CV (open it again). Universal checks, on top of whichever
  shape-specific ones the chosen shape file adds:
  1. **Invented facts** — any employer, number, outcome, deliverable, or mechanism not actually
     supported by `data/CV_GENERAL.md`.
  2. **Ownership inflation** — "led"/"built"/"drove" for something the Master CV shows was
     contributed to, not owned.
  3. **Indefensible or self-contradictory claims** — would the candidate stand behind the hook if
     pushed on a call? Does it contradict something their own history documents as a value
     elsewhere?
  4. **Structure/voice violations** — banned corporate phrasing, an achievement list instead of a
     told story, an invented deliverable.

  If a real issue turns up, fix that specific paragraph/claim and re-check — don't rewrite the
  whole letter from scratch chasing a "perfect" version. A letter that's 90% right and sent beats
  one polished forever; a genuine invented fact or ownership inflation must be fixed, not shipped
  with a caveat.
