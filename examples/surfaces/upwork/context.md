# Upwork -- positioning intent

## Role in strategy

Secondary and minimal. Alex's plan (`data/strategy.md`) is a full-time senior backend IC role;
freelancing is not part of it, and `config.yaml` has no `commercial_directions`. This surface
exists only for the occasional well-scoped backend contract that fits around employment -- an API
integration, a performance problem, a small service. Keep it current and honest about that;
don't build it out as if a freelance practice were a goal, and don't invent Fractional-CTO /
advisory positioning the strategy doesn't support.

If Alex's direction ever shifts toward client work, this is a `surface-define.md` revise, not an
update -- the role above changes first.

## Audience

Clients posting bounded backend work: adding to an existing API without breaking its consumers,
integrating a third-party service, fixing a slow endpoint, extracting a small service. They're
comparing proposals and deciding who understands the problem, not hiring a team member.

## Emphasise

- Concrete "I've done exactly this" evidence, reframed as the client's problem: payment webhooks
  that silently drop and need reconciliation + retries; a reporting query that got slow; features
  added to a shared API without a compatibility break.
- Bounded scope -- Alex is good at taking one clearly-defined piece of backend work from ticket
  to shipped. Say that plainly; it's the honest pitch and it's what these postings want.
- The stack where the evidence is real: Python, PostgreSQL, Docker, REST APIs (Celery/Redis).

## Doesn't belong here

Topics to keep off this surface, not phrasings:

- Anything that reads as "hire me long-term" or "I want ownership of a codebase" -- that's the
  employment story (LinkedIn / the targeted CV), and it makes a bounded-contract proposal read
  as someone angling for a job.
- The mentoring / PR-review / team-process angle. True, but it's employment-shaped evidence, not
  "I'll solve your problem" evidence.
- Leadership or architecture-redesign framing. Alex works well inside existing systems and
  processes; a "I'll rethink how your backend is built" pitch isn't supported and isn't what
  Alex wants.

## Tone

Plain and direct -- a bit more "here's what I can do for you" than LinkedIn, still no
agency-speak ("innovative", "results-driven", "passionate"). Alex's `Voice Material` fits here:
understated, "mostly it just has to work".

## Pinned

- **Title:** `Backend Developer -- Python / PostgreSQL / API work, available for bounded projects`
- **Rate note:** hourly, mid-market; not the differentiator, don't lead with it.
- **CTA (closes the Overview):** `Tell me the specific problem and I'll tell you honestly whether it's a good fit and roughly what it takes.`
